## 1. LLM คือ "เครื่องทำนายคำถัดไป"

LLM (Large Language Model) ถูกเทรนด้วยข้อความจำนวนมหาศาลให้ทำงานเดียว คือ
**ดูข้อความที่มีอยู่ แล้วทำนายว่า token ถัดไปควรเป็นอะไร**

```
Input:  "เมืองหลวงของประเทศไทยคือ"
Model:  → "กรุงเทพ" (ความน่าจะเป็นสูง)
        → "เชียงใหม่" (ต่ำมาก)
```

โมเดลจะทำนายทีละ token แล้วนำ token นั้นต่อท้าย input ก่อนทำนายตัวถัดไป วนแบบนี้จนจบประโยค
กระบวนการนี้เรียกว่า **autoregressive generation**

> 💡 **เทียบกับวิศวคอม:** คล้าย state machine ที่ state คือข้อความทั้งหมดที่มีอยู่
> และ transition function คือ neural network ขนาดหลายแสนล้านพารามิเตอร์

### ทำไมมันดูฉลาด
การจะทำนายคำถัดไปได้แม่นในข้อความทุกประเภท (โค้ด กฎหมาย คณิตศาสตร์ บทสนทนา)
โมเดลต้องเรียนรู้โครงสร้างของภาษาและความรู้ไปพร้อมกัน จากนั้นยังผ่านการฝึกเพิ่ม (post-training) ให้ทำตามคำสั่ง ใช้เครื่องมือ และปลอดภัย

### สิ่งที่ LLM **ไม่ใช่**
- **ไม่ใช่ฐานข้อมูล:** อาจแต่งข้อมูลที่ไม่มีจริงขึ้นมา (hallucination) → แก้ด้วย RAG ในบทที่ 7–8
- **ไม่รู้เหตุการณ์หลังวันตัดข้อมูล (knowledge cutoff)** → แก้ด้วยเครื่องมือค้นเว็บ
- **ไม่มีความจำระหว่างการเรียกแต่ละครั้ง** → ดูหัวข้อที่ 5

## 2. Token คือหน่วยนับของทุกอย่าง

โมเดลไม่ได้อ่านเป็น "ตัวอักษร" หรือ "คำ" แต่อ่านเป็น **token** ซึ่งเป็นชิ้นส่วนของข้อความ

```
"Hello world"      → ["Hello", " world"]              ≈ 2 tokens
"สวัสดีครับ"        → หลายชิ้นย่อย                        ≈ มากกว่าภาษาอังกฤษ
```

**ทำไม token สำคัญ:**
| เรื่อง | ผลกระทบ |
|---|---|
| 💰 ค่าใช้จ่าย | คิดเงินตามจำนวน token (input กับ output ราคาต่างกัน) |
| 📏 Context window | จำนวน token สูงสุดที่ส่งเข้าไปได้ในครั้งเดียว |
| ⏱ ความเร็ว | output ยิ่งยาว ยิ่งรอนาน |
| 🇹🇭 ภาษาไทย | มักใช้ token มากกว่าภาษาอังกฤษเมื่อเนื้อหาเท่ากัน |

### ราคา Claude (ต่อ 1 ล้าน token, ข้อมูล ณ มิ.ย. 2026)
| โมเดล | Model ID | Input | Output | เหมาะกับ |
|---|---|---|---|---|
| Claude Opus 5 | `claude-opus-5` | $5 | $25 | งานยาก, agent (ค่าเริ่มต้นของแล็บ) |
| Claude Sonnet 5 | `claude-sonnet-5` | $2 | $10 | งานทั่วไปปริมาณมาก |
| Claude Haiku 4.5 | `claude-haiku-4-5` | $1 | $5 | งานง่ายที่ต้องการความเร็ว |

**ตัวอย่างการคำนวณ:** ถามด้วย 500 token แล้วได้คำตอบ 1,000 token บน Opus 5
= (500 × $5 + 1,000 × $25) / 1,000,000 = **$0.0275** (ประมาณ 1 บาท)

> ตลอดหลักสูตรนี้ค่า API น่าจะอยู่ที่หลักร้อยบาท ถ้าอยากประหยัด ให้เปลี่ยน `MODEL` ในไฟล์ `lab/common.py` เป็นรุ่นที่ถูกกว่า

## 3. โครงสร้างของ API call

ทุกอย่างผ่าน endpoint เดียวคือ `POST /v1/messages`

```python
response = client.messages.create(
    model="claude-opus-5",          # ใช้โมเดลไหน
    max_tokens=16000,               # จำกัดความยาวของคำตอบ
    system="คุณคือผู้ช่วย...",        # บทบาทและกติกา (ไม่บังคับ)
    messages=[                      # ประวัติบทสนทนา
        {"role": "user", "content": "สวัสดี"},
    ],
)
```

สิ่งที่ได้กลับมา:
```python
response.content       # list ของ block: text / thinking / tool_use
response.stop_reason   # หยุดเพราะอะไร: end_turn, max_tokens, tool_use, refusal
response.usage         # input_tokens, output_tokens → ใช้คำนวณเงิน
```

### stop_reason ต้องเช็คทุกครั้ง
| ค่า | ความหมาย | ต้องทำอะไร |
|---|---|---|
| `end_turn` | ตอบจบปกติ | ใช้คำตอบได้เลย |
| `max_tokens` | คำตอบถูกตัดกลางคัน | เพิ่ม `max_tokens` หรือใช้ streaming |
| `tool_use` | โมเดลขอใช้เครื่องมือ | (บทที่ 3) |
| `refusal` | โมเดลปฏิเสธคำขอ | แจ้งผู้ใช้ |

## 4. System prompt กับ User message

| | System prompt | User message |
|---|---|---|
| คือ | "คู่มือพนักงาน" ที่ใช้ตลอดการสนทนา | "คำขอ" ของแต่ละครั้ง |
| ใครเขียน | นักพัฒนา (คุณ) | ผู้ใช้ปลายทาง |
| ใส่อะไร | บทบาท, กติกา, รูปแบบคำตอบ, ข้อมูลบริษัท | คำถาม |

ตัวอย่างสำหรับ capstone:
```
system = """คุณคือผู้ช่วยบริหารร้าน ABC ที่ใช้ระบบ ERPNext
- ตอบเป็นภาษาไทย กระชับ
- ถ้าไม่แน่ใจเรื่องตัวเลข ให้บอกว่าไม่แน่ใจ ห้ามเดา
- ห้ามแก้ไขข้อมูลในระบบโดยไม่ได้รับการยืนยัน"""
```

## 5. API เป็น Stateless (สำคัญมาก)

**Claude ไม่จำอะไรเลยระหว่างการเรียกแต่ละครั้ง** ที่แชทดูเหมือนจำได้ เป็นเพราะเราส่งประวัติทั้งหมดเข้าไปใหม่ทุกครั้ง

```python
messages = []
messages.append({"role": "user", "content": "ผมชื่อต้น"})
# → เรียก API → ได้คำตอบ
messages.append({"role": "assistant", "content": "สวัสดีครับคุณต้น"})
messages.append({"role": "user", "content": "ผมชื่ออะไร"})
# → เรียก API พร้อม messages ทั้ง 3 อัน → โมเดลตอบว่า "ต้น"
```

ผลที่ตามมา:
- บทสนทนายิ่งยาว **input token ก็ยิ่งมาก** และเสียเงินมากขึ้นทุกรอบ
- ถ้าเกิน context window ต้องย่อหรือตัดประวัติ (บทที่ 5 จะสอน)
- **นี่คือเหตุผลที่ต้องมี agent harness** ซึ่งเป็นตัวจัดการความจำให้โมเดล

## 6. Streaming

ถ้าไม่ใช้ streaming ผู้ใช้ต้องรอจนโมเดลตอบเสร็จทั้งหมด (อาจนานหลายวินาที) แล้วข้อความจึงขึ้นมาพร้อมกัน
ถ้าใช้ streaming ข้อความจะขึ้นทีละส่วนทันที ทำให้ UX ดีขึ้นมาก และช่วยกัน timeout เมื่อคำตอบยาว

```python
with client.messages.stream(...) as stream:
    for text in stream.text_stream:
        print(text, end="", flush=True)
    final = stream.get_final_message()   # ข้อความเต็ม + usage
```

## 7. Thinking และ Effort (ทำไมไม่ใช้ temperature)

บทเรียนเก่าๆ ตามอินเทอร์เน็ตมักสอนให้ปรับ `temperature` (ค่าความสุ่ม)
แต่ **Claude รุ่นใหม่ (Opus 5, Sonnet 5) ไม่รับพารามิเตอร์นี้แล้ว** ถ้าส่งไปจะได้ error 400

ของที่ใช้แทนคือ:
- **Adaptive thinking:** โมเดลตัดสินใจเองว่าจะคิดก่อนตอบมากแค่ไหน (Opus 5 เปิดไว้เป็นค่าเริ่มต้น)
- **Effort** (`low` / `medium` / `high` / `xhigh` / `max`): บอกว่าจะให้ทุ่มเทแค่ไหน
  - `low` เร็วและถูก เหมาะกับงานง่าย
  - `high` เป็นค่าเริ่มต้น
  - `xhigh` เหมาะกับงานเขียนโค้ดหรือ agent

```python
client.messages.create(..., output_config={"effort": "low"})
```

> 🎓 **บทเรียนสำคัญของอาชีพนี้:** API เปลี่ยนเร็วมาก สิ่งที่สอนเมื่อปีที่แล้วอาจใช้ไม่ได้แล้ว
> **ให้เช็คเอกสารทางการเสมอ** อย่าเชื่อ tutorial เก่า (ข้อนี้รวมถึงความรู้เก่าของ AI ด้วย)

## 8. Refusal และ Fallbacks

บางครั้งระบบความปลอดภัยของโมเดลอาจปฏิเสธคำขอ (`stop_reason == "refusal"`)
โค้ดในแล็บจึงเปิด **`fallbacks: "default"`** ไว้ ถ้า Opus 5 ปฏิเสธ API จะส่งคำขอเดิมไปให้โมเดลสำรองที่เหมาะสมทำต่อให้อัตโนมัติ
ฟีเจอร์นี้เป็น beta จึงต้องเรียกผ่าน `client.beta.messages` และส่ง header `server-side-fallback-2026-07-01`
ทั้งหมดนี้ห่อไว้ใน `lab/common.py` แล้ว ไม่ต้องเขียนซ้ำในทุกไฟล์
