# Capstone — ERPNext AI Business Assistant

⏱ ประมาณ 3–4 สัปดาห์ · นำทุกบทมารวมเป็น portfolio ชิ้นใหญ่

## เป้าหมายของโปรเจกต์
ระบบผู้ช่วยบริหารธุรกิจที่เจ้าของร้านใช้ได้จริง:
- **ERPNext** เป็นแหล่งข้อมูลธุรกิจ (สต็อก ขาย ลูกค้า)
- **Web App** มี dashboard และหน้าแชทภาษาไทย
- **AI Agent** ตอบคำถาม วิเคราะห์ และร่างเอกสาร โดยมีคนอนุมัติก่อนทำงานสำคัญ

## 2. ขอบเขตงาน (Scope)

### Must have (ต้องมี)
- [ ] ถามสต็อก: "เมาส์เหลือเท่าไร", "อะไรใกล้หมด"
- [ ] ถามยอดขาย: "เดือนนี้ขายได้เท่าไร เทียบเดือนก่อน", "ลูกค้ารายใหญ่ 5 อันดับ"
- [ ] ถามนโยบายจากเอกสาร (RAG) พร้อมแหล่งอ้างอิง
- [ ] ร่างใบเสนอราคา (Draft) พร้อมปุ่มอนุมัติ
- [ ] Dashboard: ยอดขายเดือนนี้, สินค้าใกล้หมด, หนี้ค้างรับ
- [ ] Eval อย่างน้อย 30 เคส พร้อมผลลัพธ์ใน README
- [ ] Log ค่าใช้จ่ายและ latency

### Should have (ควรมี)
- [ ] ERPNext MCP server ใช้งานได้กับ Claude Desktop
- [ ] แผนสั่งซื้อ: วิเคราะห์ยอดขายย้อนหลังกับสต็อก แล้วร่าง Purchase Order
- [ ] หนี้ค้างรับ: รายการใบแจ้งหนี้ที่เลยกำหนด พร้อมร่างข้อความทวงถามอย่างสุภาพ (ร่างอย่างเดียว ไม่ส่งเอง)
- [ ] Memory: จำกฎของร้าน และความชอบของผู้ใช้
- [ ] Webhook: แจ้งเตือนเมื่อสต็อกต่ำ

### Nice to have (ถ้ามีเวลา)
- [ ] Login ด้วยบัญชี ERPNext และแยกสิทธิ์ตาม role
- [ ] รายงานประจำสัปดาห์อัตโนมัติ (ใช้ Batch API เพื่อประหยัด)
- [ ] รองรับการอัปโหลดรูปใบเสร็จหรือใบสั่งซื้อ แล้วดึงข้อมูลออกมา (Claude อ่านรูปภาพได้)
- [ ] ทำเป็น Frappe Custom App

## 3. แผนงาน 4 สัปดาห์

| สัปดาห์ | งาน | ผลลัพธ์ |

| **1** | เตรียมข้อมูลตัวอย่างใน ERPNext (สินค้า 30 ตัว, ลูกค้า 10 ราย, ใบขายย้อนหลัง 3 เดือน), เขียน `erp_client` และ `erp_tools` พร้อม unit test | ข้อมูลพร้อม และเครื่องมือทำงานได้ถูกต้องโดยยังไม่ใช้ AI |

## 6. เตรียมเล่าโปรเจกต์ตอนสัมภาษณ์ (3 นาที)

ใช้โครง **STAR**:
1. **Situation:** "ร้านค้า SME ใช้ ERPNext แต่เจ้าของไม่มีเวลาดูรายงาน"
2. **Task:** "ผมอยากให้เจ้าของถามเป็นภาษาไทยได้เลย และให้ระบบช่วยร่างเอกสารได้อย่างปลอดภัย"
3. **Action:** "ผมออกแบบ agent ที่มีเครื่องมือ X ตัว แยกระดับความเสี่ยง ทำ RAG ภาษาไทยด้วย hybrid search และสร้าง eval 35 เคส..."
4. **Result:** "ความแม่นยำเพิ่มจาก 60% เป็น 91% ค่าใช้จ่ายลดลง 40% ด้วย caching"
5. **บทเรียน:** "สิ่งที่แปลกใจที่สุดคือ ปัญหาส่วนใหญ่อยู่ที่ description ของเครื่องมือ ไม่ได้อยู่ที่ตัวโมเดล"

## 7. คำถามสัมภาษณ์ที่ควรตอบได้หลังเรียนจบ

<details><summary>1. RAG ต่างจาก fine-tuning อย่างไร และเลือกใช้เมื่อไหร่</summary>

RAG ดึงความรู้จากภายนอกมาใส่ context ตอนตอบ ข้อดีคืออัปเดตง่ายและอ้างอิงแหล่งที่มาได้ เหมาะกับการเพิ่มความรู้
Fine-tuning ปรับน้ำหนักของโมเดล เหมาะกับการเปลี่ยนสไตล์หรือรูปแบบ ไม่เหมาะกับการสอนข้อเท็จจริงใหม่
งานส่วนใหญ่ควรเริ่มจาก prompt แล้วตามด้วย RAG ก่อน (บทที่ 8)
</details>

<details><summary>2. Agent ต่างจาก workflow อย่างไร</summary>

Workflow ใช้โค้ดกำหนดลำดับขั้นตายตัว ส่วน agent ให้โมเดลตัดสินใจขั้นต่อไปเองในลูป
agent ยืดหยุ่นกว่าแต่แพงกว่าและคาดเดายากกว่า ถ้ารู้ขั้นตอนล่วงหน้าควรใช้ workflow (บทที่ 4)
</details>

<details><summary>3. ป้องกัน agent วนลูปไม่รู้จบอย่างไร</summary>

จำกัดจำนวนรอบ, จำกัดงบประมาณ, ตรวจจับการเรียกเครื่องมือซ้ำด้วย input เดิม และเขียน error message ที่ช่วยให้โมเดลแก้ต่อได้ (บทที่ 4)
</details>

<details><summary>4. Prompt injection คืออะไร ป้องกันอย่างไร</summary>

คือการฝังคำสั่งไว้ในข้อมูลที่ agent อ่าน ป้องกันด้วยหลายชั้น: แยกข้อมูลด้วย tag, ให้สิทธิ์น้อยที่สุด, ให้คนอนุมัติงานเสี่ยง, บังคับกฎในโค้ด และตัดช่องทางส่งข้อมูลออก
ต้องระวัง lethal trifecta เป็นพิเศษ (บทที่ 6)
</details>

<details><summary>5. วัดว่าระบบ LLM ดีขึ้นได้อย่างไร</summary>

สร้างชุด eval จากเคสจริงและเคสที่เคยพัง ใช้ code grader ร่วมกับ LLM judge แบบผ่าน/ไม่ผ่าน ตรวจความตรงของ judge กับคน
ทำ error analysis แล้วเปรียบเทียบผลก่อนและหลังแก้ (บทที่ 12)
</details>

<details><summary>6. ลดค่าใช้จ่ายของระบบ LLM อย่างไร</summary>

เริ่มจากสิ่งที่ไม่ต้องแลกกับคุณภาพ: prompt caching, ลด input และ output
จากนั้นใช้ Batch API กับงานที่ไม่ต้องได้ผลทันที แล้วค่อยลด effort หรือใช้โมเดลเล็กลงโดยวัดคุณภาพด้วย eval
และวัดค่าใช้จ่ายต่องานที่สำเร็จ ไม่ใช่ต่อ request (บทที่ 12)
</details>

<details><summary>7. ทำไมแชทยาวๆ ถึงแพงขึ้นเรื่อยๆ</summary>

เพราะ API เป็น stateless ต้องส่งประวัติทั้งหมดใหม่ทุกครั้ง input token จึงเพิ่มขึ้นทุกรอบ
แก้ได้ด้วย caching, compaction และการล้างผลของเครื่องมือเก่า (บทที่ 1 และ 5)
</details>

<details><summary>8. MCP คืออะไร</summary>

มาตรฐานเปิดสำหรับเชื่อม LLM app กับเครื่องมือและข้อมูล เขียน server ครั้งเดียวใช้ได้กับทุก host
มี tools, resources และ prompts ส่งผ่าน stdio หรือ HTTP (บทที่ 10)
</details>

<details><summary>9. Hybrid search คืออะไร ทำไมต้องใช้</summary>

คือการรวมผลค้นหาแบบ keyword (BM25) กับแบบ vector เพราะ vector เก่งเรื่องความหมาย แต่พลาดง่ายกับรหัสและชื่อเฉพาะ
รวมผลด้วย RRF แล้ว rerank (บทที่ 7) ภาษาไทยต้องตัดคำก่อนทำ BM25
</details>

<details><summary>10. ถ้า RAG ตอบผิด จะ debug อย่างไร</summary>

ดูก่อนว่าเอกสารที่ถูกต้องอยู่ใน top-k หรือไม่ ถ้าไม่อยู่ ปัญหาอยู่ที่ retrieval (การดึงข้อความ, chunking, คำค้น)
ถ้าอยู่ ปัญหาอยู่ที่ generation (prompt, เอกสารขัดแย้งกัน, ข้อมูลมากเกินไป) (บทที่ 8)
</details>
