# โปรเจกต์ Portfolio 5 ชิ้น

แต่ละโปรเจกต์ควรมี:
- README ที่บอกว่าแก้ **ปัญหาอะไร** ใช้ **สถาปัตยกรรมแบบไหน** (มีรูป diagram) และ **วัดผลอย่างไร**
- demo ที่คนกดลองได้ (Streamlit / Gradio / เว็บ) หรือคลิปสั้นประมาณ 1–2 นาที
- `.env.example` และห้าม commit API key เด็ดขาด

---

## 1. Thai Document Q&A (RAG พื้นฐาน) — เฟส 2
ถามตอบจากเอกสาร PDF ภาษาไทย เช่น ระเบียบมหาวิทยาลัย, พ.ร.บ. หรือคู่มือบริษัท
- ตัดคำไทยด้วย `pythainlp`, ใช้ embeddings + pgvector/Chroma
- **ต้องแสดงแหล่งอ้างอิง** (เลขหน้าที่ใช้ตอบ)
- จุดเด่น: แก้ปัญหาเฉพาะของภาษาไทย

## 2. RAG ที่วัดผลได้ — เฟส 2–4
ต่อยอดจากโปรเจกต์ที่ 1
- สร้างชุดคำถามทดสอบ 30–50 ข้อพร้อมคำตอบที่ถูก
- เทียบวิธี chunking และ vector กับ hybrid search แล้วทำตารางผลลัพธ์ใส่ README
- จุดเด่น: แสดงว่าคุณ **ทำงานแบบวิศวกร** คือมีการวัดผลก่อนตัดสินใจ

## 3. Coding / Research Agent เขียนเองจากศูนย์ — เฟส 3
เขียน agent loop เองโดยไม่ใช้ framework
- เครื่องมือ: ค้นเว็บ, อ่านไฟล์, เขียนไฟล์, รันคำสั่ง (ใน sandbox)
- มี permission layer (ถามก่อนรันคำสั่งอันตราย), จำกัดจำนวนรอบ และ log ทุก step
- จุดเด่น: แสดงว่าเข้าใจ **agent harness** จริง ไม่ได้แค่เรียก library

## 4. ERPNext AI Assistant ผ่าน MCP ⭐ — เฟส 3
**โปรเจกต์นี้เหมาะกับคุณเป็นพิเศษ เพราะมี ERPNext อยู่แล้ว**
- สร้าง MCP server ที่ครอบ ERPNext REST API ไว้ เช่น ดูสต็อก, ค้นลูกค้า, สร้างใบเสนอราคา (draft)
- ให้ Claude หรือ agent เรียกใช้ผ่านภาษาธรรมชาติ เช่น "สินค้าไหนใกล้หมดสต็อกบ้าง"
- เน้นความปลอดภัย: งานอ่านทำได้เลย ส่วนงานเขียนต้องให้คนยืนยันก่อน
- จุดเด่น: ต่อ AI เข้ากับ **ระบบธุรกิจจริง** ซึ่งบริษัท SME ไทยต้องการมาก

## 5. Production-ready Service — เฟส 4
นำโปรเจกต์ 1 หรือ 4 ขึ้น production
- FastAPI + Docker + deploy ขึ้น cloud
- มี tracing (Langfuse), eval รันอัตโนมัติใน GitHub Actions, rate limit และ prompt caching
- README มีหัวข้อ "ค่าใช้จ่ายต่อ 1,000 คำถาม" และ "latency เฉลี่ย"
- จุดเด่น: หัวข้อเหล่านี้คือสิ่งที่ hiring manager อยากเห็นที่สุด
